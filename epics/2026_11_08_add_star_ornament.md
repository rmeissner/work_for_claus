# Plan: Slot-Together Star Ornament

Component: `tools/stlkit/` (new, shared Python toolkit for generating STL models) and `models/star-ornament/` (new model).

PR strategy: merge each

---

## Overview

Add a Christmas star ornament that is printed flat as two parts and slotted together into a 3D star. The model is generated by a script, not drawn by hand, so it can be tweaked by changing parameters and regenerated.

The generation code is split in two:

- **Reusable toolkit** (`tools/stlkit/`): 2D shapes, extrusion, plate layout, mesh checks and STL export. Future models import it.
- **Model-specific script** (`models/star-ornament/`): the star's parameters and geometry, built on the toolkit. It lives next to the model's `project.json` and `.stl`.

PRs:

1. **Plan** (this PR): the epic specification only.
2. **STL toolkit**: the `tools/stlkit` package, its tests, a CI workflow and a README section on generating models.
3. **Star ornament model**: generator script, tests, `project.json` and the generated STL. Depends on 2.
4. **Cleanup**: remove this specification file. Depends on 3.

Phases run one after another; there is nothing to parallelize.

## Architecture Decision

### Python with manifold3d

- Models are generated with **Python 3.13** and the [manifold3d](https://github.com/elalish/manifold) library (pip, prebuilt wheels). Manifold gives robust 2D (`CrossSection`) and 3D (`Manifold`) booleans, offsets and extrusion, and guarantees watertight (manifold) output, which slicers need.
- **numpy** is used for vertex/triangle arrays and the STL writer. No other runtime dependency.
- Dependencies are pinned in `tools/requirements.txt` (manifold3d, numpy, pytest). Python tooling lives under `tools/`, apart from `webapp/`.
- The toolkit is a plain package (`tools/stlkit/`), not published. Model scripts add `tools/` to `sys.path` (one small helper line, documented in the README) so they run with `python models/<slug>/generate.py` from the repository root without installing anything but the requirements.

### Toolkit scope (`tools/stlkit`)

Only what is generic and needed by the star, so it stays small:

| Module | Content |
|---|---|
| `shapes.py` | 2D helpers returning `CrossSection`s: `star(points, outer_radius, inner_radius)`, `regular_polygon(...)`, `ring(outer, inner)`, `bar(start, end, width)` (a rectangle between two points), `round_corners(shape, radius)` (offset in, then out). |
| `solids.py` | `extrude(shape, height)` and `layout_on_plate(parts, gap)`: places parts side by side on the XY plane (Z ≥ 0), centered around the origin, separated by `gap`. |
| `checks.py` | `assert_printable(manifold, *, max_size)`: non-empty, manifold/watertight (`status` OK, genus check optional), sits on Z = 0, fits into `max_size` (default 220 × 220 × 250 mm — adjust once Claus' build volume is known). |
| `export.py` | `write_stl(manifold, path, name)`: writes a **binary STL** (small files; the webapp's three.js `STLLoader` reads binary and ASCII). Normals computed per facet. Output is deterministic for the same input. |

### Model folder layout

```
models/star-ornament/
├── project.json
├── star-ornament.stl     # generated, committed (the webapp shows it)
├── generate.py           # model-specific: parameters + geometry, writes the STL
└── test_generate.py      # model-specific tests (pytest)
```

- Both parts are in **one STL**, laid out flat side by side. The webapp shows the first STL of a folder (multi-STL support is rmeissner/work_for_claus#5), and one plate is also how it gets printed.
- The webapp only globs `project.json` and `*.stl`, so the Python files in the model folder do not affect it.
- The STL is regenerated and committed by hand. CI regenerates it and fails if the committed file is out of date (see Tech Specs).

### Alternatives Considered

- **Python + numpy only** (own triangulation and extrusion): no dependency, but slots, windows and rounding need general 2D booleans; writing them ourselves is error-prone and hard to review.
- **OpenSCAD**: the classic parametric 3D-printing tool, but needs the OpenSCAD binary locally and in CI, and its language is less suited to shared, tested helpers.
- **CadQuery / build123d**: full B-rep CAD with fillets, but a heavy OCCT dependency for flat, extruded parts.
- **Two STL files** (one per part): cleaner per-part printing, but the webapp would only show one of them until #5 is done.

## Tech Specs

### Star design

Two flat parts with the **same star outline**, printed lying down, slotted together at right angles along the star's vertical axis. Assembled, they form a 3D star.

To make it look special, each part is a **faceted wireframe star** (see the prototype sketch below): an outer frame plus ribs from the center to every tip and every notch, leaving ten triangular windows. This draws the facet edges of a classic 3D "origami" star, so even the flat parts look three-dimensional, and the assembled ornament shows the facets from every side. It also saves filament and lets light through when hung near tree lights.

```
   part A (slot from below)        part B (slot from above)
            /\                              /|\
           /██\                            / | \
     _____/ ██ \_____                _____/  |  \_____
     \  ___ ▀▀ ___  /                \  ___ ██ ___  /
      \/   \||/   \/                  \/   \██/   \/
      /  _/ || \_  \                  /  _/ ██ \_  \
     /__/   ||   \__\                /__/   ██   \__\
```

Default parameters (all in `generate.py`, millimeters):

| Parameter | Default | Notes |
|---|---|---|
| `POINTS` | 5 | |
| `OUTER_RADIUS` | 45 | center to tip → ~90 mm tall star |
| `INNER_RADIUS` | 22 | center to notch; fatter than a regular pentagram (17.2) so arms are sturdy |
| `THICKNESS` | 3.0 | part thickness = slot width before clearance |
| `FRAME_WIDTH` | 2.6 | outer frame |
| `RIB_WIDTH` | 2.2 | facet ribs (≥ 5 perimeters with a 0.4 mm nozzle) |
| `TIP_ROUNDING` | 1.0 | rounds tips and outer corners so they don't peel or snag |
| `HUB_RADIUS` | 5.5 | solid center where the ribs meet |
| `SLOT_CLEARANCE` | 0.2 | slot width = `THICKNESS + SLOT_CLEARANCE` |
| `SPINE_WALL` | 2.4 | solid material on each side of the slot |
| `LOOP_OUTER` / `LOOP_INNER` | 4.0 / 2.0 | radii of the hanging loop |
| `PLATE_GAP` | 5 | gap between the parts on the plate |

Geometry:

- **Outline:** `star(POINTS, OUTER_RADIUS, INNER_RADIUS)` with a tip at +Y, rounded by `TIP_ROUNDING`.
- **Windows:** outline inset by `FRAME_WIDTH`, minus ribs (`bar` from the center to each tip and notch, `RIB_WIDTH` wide), minus the hub, minus the **spine**: a band along the vertical axis, `SLOT_CLEARANCE + THICKNESS + 2 × SPINE_WALL` wide, so the slot always has solid walls. Part = outline − windows.
- **Slots** along the vertical axis, meeting at `m = (OUTER_RADIUS − INNER_RADIUS) / 2` (half way between the bottom notch at `y = −INNER_RADIUS` and the top tip):
  - Part A: slot from the bottom notch up to `m`.
  - Part B: slot from the top tip down to `m`.
  - The slot lengths add up to the full axis length, so the parts' outlines line up when assembled.
- **Hanging loop:** a ring (`LOOP_OUTER`/`LOOP_INNER`) on part A, centered above its top tip and fused to it. It has to stick out above the tip: part B's top arm, split by its slot, hugs part A's top arm on both sides and would cover a hole drilled through the tip.
- **Printability:** every part is a plain extrusion (no overhangs, no supports), flat on the bed. Minimum feature width ≥ 2 mm.
- **Plate:** `layout_on_plate([A, B], PLATE_GAP)`, then `assert_printable`, then `write_stl(..., "models/star-ornament/star-ornament.stl")`.

### `project.json`

```json
{
  "name": "Star ornament",
  "description": "Slot-together Christmas star: two flat, faceted parts that slide into each other to form a 3D star.\nPrint both parts flat without supports (PLA, 0.2 mm layers). Push part B down onto part A at a right angle; tie a ribbon through the loop."
}
```

### Tests (pytest)

- `tools/stlkit/tests/`:
  - `star` has `2 × points` vertices with the expected radii; `bar` has the expected length and width; `round_corners` keeps the area within a tolerance.
  - `extrude` returns a manifold with volume = area × height.
  - `layout_on_plate` puts all parts on Z = 0 without overlapping bounding boxes, separated by `gap`.
  - `assert_printable` accepts a cube and rejects an empty manifold, a part below Z = 0 and a part larger than `max_size`.
  - `write_stl` writes a valid binary STL (80-byte header, triangle count matches the file size) that round-trips to the same triangle count; same input → identical bytes.
- `models/star-ornament/test_generate.py`:
  - both parts are manifold and printable; the plate fits the build volume;
  - slot width is `THICKNESS + SLOT_CLEARANCE` and the slot lengths add up to the axis length;
  - **assembly check:** rotate part B by 90° about the vertical axis, place both centered, and check the intersection volume is (close to) zero — i.e. they slide together without collision;
  - the narrowest rib/wall is ≥ 2 mm (offset the 2D part by −1 mm and check it doesn't fall apart into more pieces than expected, or an equivalent check);
  - the committed `star-ornament.stl` equals freshly generated bytes.

## Open Questions and Assumptions

- **Build volume:** Claus' build volume isn't documented; `assert_printable` defaults to 220 × 220 × 250 mm. The plate is ~180 × 90 mm. Adjust the default when known.
- **Slot clearance:** 0.2 mm assumes a reasonably calibrated printer (see the calibration cube). If the fit is too tight or loose, change `SLOT_CLEARANCE` and regenerate.
- **Material:** PLA assumed; no colors or multi-material.
- **Byte-identical STL check:** assumes manifold3d output is deterministic for the pinned version. If it differs between platforms, the test falls back to comparing volume, bounding box and triangle count.
- The two-STL question is left to rmeissner/work_for_claus#5.
