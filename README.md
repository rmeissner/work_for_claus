# Work for Claus

This repo contains 3D models for our printer Claus

## Webapp

The `webapp/` folder contains a [Vite](https://vite.dev) + React + TypeScript app for browsing the models. The header has a System / Light / Dark theme toggle; the choice is stored in `localStorage` (System follows the OS). The header also shows the app version (`version` in `webapp/package.json`, bump it by hand) and the short hash of the commit the app was built from (`CF_PAGES_COMMIT_SHA` on Cloudflare Pages, `dev` for local builds).

Requirements: Node.js 26 (see `.nvmrc`).

```bash
cd webapp
npm install
npm run dev        # start the dev server
npm run build      # type-check and build into webapp/dist
npm run lint       # lint with oxlint
npm run typecheck  # type-check only
npm test           # run the unit tests (Vitest)
```

The app icon is `webapp/public/favicon.svg` (Claus, our printer). The PNG icons (`favicon-32.png`, `apple-touch-icon.png` at 180 px, `icon-192.png`, `icon-512.png`) were rendered from it with a Playwright (Chromium) screenshot of the SVG at each size and a transparent background (`apple-touch-icon.png` with square, opaque corners, because iOS rounds them itself and fills transparency with black); re-render them the same way after changing the SVG.

## Adding a model

Each model lives in its own folder under `models/`. The folder name is the model's slug (used in links):

```
models/
└── calibration-cube/
    ├── project.json
    └── cube.stl
```

- `project.json` holds a non-empty `name`, a non-empty `version` (free form, e.g. `"1.0"`, bumped by hand when the model changes; shown next to the name), a plain-text `description` and a non-empty `files` list; other keys are ignored:

  ```json
  {
    "name": "Calibration cube",
    "version": "1.0",
    "description": "20 mm cube to calibrate X/Y/Z steps.",
    "files": [{ "file": "cube.stl" }]
  }
  ```

- `files` lists the model's STL files in the order they are shown. Each entry has the file name in `file` (a plain `.stl` file name in the model's folder, no duplicates) and an optional `name` as label; the label defaults to the file name.
- Folders with a missing or invalid `project.json` are skipped with a warning in the browser console. A listed file that is not in the folder is dropped with a warning (the model is skipped if none is left), and an STL file that is not listed is ignored with a warning.

## Generating models

Some models are generated by Python scripts instead of being drawn by hand, so they can be tweaked by changing parameters and regenerated. The scripts use the shared toolkit in `tools/stlkit` (2D shapes, extrusion, plate layout, printability checks and STL export), built on [manifold3d](https://github.com/elalish/manifold).

Requirements: Python 3.13.

```bash
pip install -r tools/requirements.txt
python models/<slug>/generate.py   # regenerate the model's STL (run from the repository root)
pytest                             # run the toolkit tests and check that the committed STLs are up to date
ruff check                         # lint the Python code (add --fix to apply safe fixes)
ruff format                        # format the Python code
```

- CI runs `ruff check`, `ruff format --check` and `pytest` for every pull request, so run `ruff check` and `ruff format` before committing. The rules are in `ruff.toml`.
- A model folder holds only `generate.py`, `project.json` and the STLs. Model scripts are not unit tested; models are reviewed through the rendered preview. `pytest` checks the toolkit and, for every `models/*/generate.py`, that the committed STLs match what the script writes (`tools/stlkit/tests/test_models.py`).
- Every `generate.py` must have a `main()` that writes the STLs next to the script (`Path(__file__).with_name(...)`). Helpers that more than one model could use go into `tools/stlkit`.
- Scripts add `tools/` to `sys.path` to import the toolkit, so nothing needs to be installed besides the requirements.
- The generated `.stl` is committed, because the webapp shows it.

## Contributing

- Open a pull request against `main`; the description is pre-filled from `.github/pull_request_template.md`. Keep each PR to one purpose and delete the sections that don't apply.
- `.github/CODEOWNERS` requests a review from every collaborator (GitHub skips the PR's author). A new collaborator has to be added to that file by hand.
- The `CI - Models`, `CI - Webapp` and `CI - Workflows` checks run on every pull request and must pass before it is merged.
